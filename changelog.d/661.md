fix(wf): ready gate decisions land at the wave boundary, and deferred gates say why

Gate decisions used to be reachable only when no agent node was ready: the
gate pick sat after the runner's blocking agent-wave branch, so a gate whose
ancestor had already finished — including the harvest-on-death shape where a
child exits rc=1 with a valid answer — produced ZERO events until every
sibling lane's wave ended (a field incident: 50 silent minutes, status
showing the gate ready with no reason). The runner now drains the
NON-BLOCKING, zero-spawn decisions at each wave boundary, BEFORE the next
wave spawns: a valid answer releases, an output-precondition miss on the
gate's own `requires` paths refuses it typed, a false `when` skips, and the
prune cascade re-runs after every commit (prune, then decide — cascade
victims commit `node.skipped all deps pruned` exactly as before, and a
pruned subtree never spawns). Decisions that PARK or HOLD still evaluate
after the wave so ready agents are never stranded, and the pick keeps its
declaration-order law. A gate whose decision a wave defers journals
`gate.deferred {node, by}` naming the blocking agents, and `status` surfaces
it as that gate's `blocked_by` while the runner is live — a deferred gate is
never silent again. An ancestor finishing mid-wave still waits for the wave
boundary; the drain is boundary-only.

Tests: tests/test_gate_wave_boundary_p2g.py (RED on base reproduces the
incident window locally; GREEN pins the boundary skip, the after-wave hold,
deferred-reason visibility and clearing, cascade precedence, and the
requires refusal).
