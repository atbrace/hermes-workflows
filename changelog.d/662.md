fix(ci): bootstrap the pinned core with uv in the ci-parity container

Two-stage gap, one fix. (1) apt carried no pip at all — kept, pip now
installs uv. (2) The real root cause: the pinned core's dependency set is
uv-only — 45 pins marker-gated to python>=3.14 (image default is 3.12, so
pip resolves ZERO of them) plus a pillow override living in uv.lock that
pip never reads, and a pyproject pin-graph (browser-harness==0.1.13 pins
pillow==12.3.0 vs hermes-agent's pillow==13.0.0) that is unsatisfiable
without the override. pip -e "succeeded" while installing nothing, and the
WARN line swallowed the fallout, masking the suite's real verdict. The
bootstrap now runs `uv sync --python 3.14` (uv fetches a standalone 3.14;
the lock's overrides resolve the pillow pair) and symlinks the venv's
hermes onto PATH. Measured on the cluster: ruamel import + hermes
--version green at the pinned SHA on ubuntu:24.04.
