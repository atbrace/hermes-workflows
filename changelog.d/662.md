fix(ci): make the ci-parity container mirror the upstream gates environment

Dry-run receipts showed the parity container had drifted from the gates
it mirrors in four independent ways, each masking the suite's real
verdict:

1. apt carried no pip — the bootstrap died before anything could run.
2. The pinned core is uv-only even with pip: all 45 base pins are
   marker-gated `python_version >= '3.14'` (image default 3.12 → pip
   resolves ZERO), and the pyproject pin-graph (browser-harness==0.1.13
   pins pillow==12.3.0 vs hermes-agent's pillow==13.0.0) is unsatisfiable
   without the pillow override inside uv.lock. `pip -e` "succeeded"
   installing an empty package. The bootstrap now installs uv and runs
   `uv sync --python 3.14` (uv fetches a standalone CPython 3.14), and
   puts a two-line `uv run` shim at /usr/local/bin/hermes — the uv-synced
   env lives outside the checkout, so symlink-to-.venv was a dangling
   promise (measured: no .venv at project root).
3. apt nodejs is 18; upstream gates pin node 22 (ci.yml setup-node) —
   every .mjs arm died on --experimental-strip-types (rc=9, 46 files).
   NodeSource setup_22.x now runs first; if the repo fetch fails the leg
   warns instead of masquerading.
4. The scrub-audit leg runs git, but crun ships a file copy without
   .git — it now skips loudly, per the parity contract that a leg which
   cannot run must announce itself rather than fake a red.

Measured on the cluster at the pinned SHA: uv sync installs the graph,
ruamel imports, hermes runs (uv run), node 22 arms parse. Full parity
dry-run verdict rides in the PR discussion.
