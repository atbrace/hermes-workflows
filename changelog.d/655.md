repair(wf): orphaned lane incumbents stop deduping every later run

A lane entry whose run dir is gone (wedge quarantine renames, any manual
removal) read `orphaned` — not in the finished set, so `run` on the same
`lane_key` deduped forever to a run that cannot be resumed: `find_run` matches
exact dir names and no verb clears an entry. A missing dir has no state to
protect, so orphaned incumbents now admit the fresh run, overwrite the entry,
and report `superseded_orphan=<old run_id>` for auditability. The pinned test
that asserted the dedupe-row contract is flipped deliberately; the published
contract docs are updated in the same commit.
