fix(wf): completion honesty — a died-but-harvested node refuses run-level green

The run-state fold reported `completed=True` over a node that died and only had
its answer harvested: the validate-policy clamp launders the `partial` death to
`done` (the record's `clamped` stamp names the verdict it replaced), and a raw
`failed` record with a schema-valid harvest answer folds the same way. Neither
arm enters `failed_nodes`, so every downstream reader of run-level state trusted
a green that hid a dead node. The judgment now lives in one predicate
(`_died_but_harvested`), the fold derives a `completed_over_dead_node` node-id
list beside `completed` in the same pass, and a non-empty list forces
`completed=False` — it can refuse a green, never grant one. `failed_nodes`
semantics are untouched: a clamped-done node is not retroactively marked failed,
and the new list is derived at read time, so runs already on disk report
differently with no migration.
