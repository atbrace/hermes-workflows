feat(door,runner): per-node call/token ceilings, enforced mid-run

An agent node can declare max_api_calls / max_input_tokens (non-negative ints,
validated at the door like the other numeric budget knobs). The enforcement
reader is the telemetry sidecar the ledger already produces: the runner samples
it read-only at the poll seam it already keeps, and samples once more at child
exit — a ceiling blown between polls cannot commit done. On EXCEED the runner
SIGKILLs the child's process group like the wall-kill, proves the tree dead,
and commits the node failed with the new terminal class ceiling_exceeded
(outside both retry ladders, like budget_exhausted). Ceilings are PER ATTEMPT:
a re-driven attempt rewrites the sidecar, so worst-case exposure is
attempts x ceiling, both bounded. The record names the ceiling, the declared
and observed values; accounting reports the declared shape where
task_total_ceiling said not_enforced.

Tests: tests/test_node_call_ceilings.py — door validation, terminal-class
membership, end-to-end typed death of a climbing fake child, the exit-race leg
(RED at the first feature commit: overshooting child committed done), the
per-attempt fold-boundary leg, and negatives (undeclared runs byte-identical,
declared-but-not-exceeded completes with telemetry folded).
