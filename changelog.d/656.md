fix(runner): the seat pool read path enforces the admission band

The door validates the seat-cap knob at admission but the pool's read of
<seats>/.cap trusted any positive integer, so a corrupt or hand-edited cap
file silently raised the estate-wide pool ceiling past the band the platform
was sized for (probe: .cap=640 admitted 640 seats at a 64 ceiling). A recorded
value outside [SEAT_CAP_FLOOR, SEAT_CAP_CEILING] now takes the exact corrupt
path: ONE stderr WORKFLOW_SEAT_POOL_WARN naming the value and the band
(WORKFLOW_KNOB_WARN shape), then re-seed from the validated seed — or report
no pool truth when the pool is read-only. The read path and the admission door
now enforce one band; an out-of-band file never silently wins.

Tests: tests/test_pool_seat_cap_mg5o2.py (out-of-band .cap re-seeds, warn line
shape, read-only degradation) and tests/test_pool_seat_cap_fifo_mg5o2.py
(in-band fixture values).
