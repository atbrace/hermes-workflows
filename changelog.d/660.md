fix(ci): the ci-parity helper ships its generated job body inside the repo

`ci/ci-parity.sh` generated its per-run job script under the host's `/tmp`,
but the container runtime stages only files inside the repo directory
(git-tracked plus untracked, minus anything git-ignored). The job body never
crossed to the node: every fresh parity run died on the container's first
command — a `cp` of the never-shipped `/tmp` path — exited rc=1, and cached a
one-hour FAIL verdict. The generated script is now written into the repo
directory (`.ci-job-$$.sh`, untracked and deliberately NOT git-ignored — an
ignore rule would exclude it from staging and reproduce the same failure),
the container-side copy reads the repo-relative path, and a non-repo job
path is refused up front with a named guard. Cleanup and the `.ci-verdict`
cache are unchanged.

Proof is a dry-run of the helper itself (no hermetic test is possible for a
container-staging bug): RED on the base tree reproduced the exact
`cp: cannot stat '/tmp/ue-ci-job-*.sh'` death; at head the copy succeeds and
the shipped body streams 366 per-file suite results at rc=0 node-side.
