# The death table — every typed `error_class`, indexed

One row per already-typed `error_class`: **signature -> where it surfaces ->
the one documented repair**. A pure index over shipped behavior: this table
adds no behavior and documents no new repair — every repair row is a pointer
into the law already written (AGENTS.md §3d, [grammar.md](grammar.md),
[operations.md](operations.md), [operator-playbook.md](operator-playbook.md)).
Read the class, not the prose; the row tells you which doc holds the law.

The set is closed and pinned to the code: `wf.py ERROR_CLASSES`, both ways, by
`tests/test_docs_hw-3c2.py` (the pipe-list sibling pin is
`tests/test_error_class_doc_sync.py`). A class added to the frozenset without
a row here fails the build; an invented row fails it too.

Signature = what you actually see. Where = which artifact carries it. Repair =
the one sanctioned move.

| error_class | signature | where it surfaces | the one documented repair |
|---|---|---|---|
| `answer_schema_invalid` | rc≠0 death whose capture holds a fenced answer that PARSES but fails the node schema; the error names the `validate()` errors, not CLI noise | `node.failed` + node record; terminal — neither ladder touches it | fix the answer shape against the node's `schema` and re-drive by amend (grammar.md) |
| `bead_close` | commit-edge read-back `bead_close_unproven: <id>: <reason>` — the runner's own `bd show` saw a status that is not `closed` | `node.failed` on a node declaring `bead_close`; the measured row rides `bead_close_receipt` | actually close the bead, or answer `close-pending: <reason>` as the honest non-claim, then re-drive (grammar.md) |
| `budget_exhausted` | pre-dispatch RunBudget refusal — `dispatch.refused` carries the class; ZERO attempts billed, the seat never touched | the event + `budget_ledger.json` (`never_launched`); the run finalizes `partial` with the derived `budget` view on `status` | raise the cap by amend — budget keys are policy, efp-exempt, so committed nodes stay frozen (operations.md §RunBudget) |
| `cancelled` | `cancelled by stop`, or a fan-out straggler cancelled once `quorum` was met | the node record; the run reads `stopped`, never `failed` — this row is not a death | `wait` to re-drive the stopped run (AGENTS.md §3d) |
| `cap_exhausted` | turn-cap death, typed only when the core quiet-turn report stamps `max_iterations_reached(n/m)` — prose about turn limits is never trusted | record + clocks read `phase: expired` / `exhaustion_reason: turn_cap`; an untyped budget death stays `unknown` | amend the goal to a resume prompt past the cap (and size `max_turns` from measured latency); the optional one-field core patch makes untyped budget deaths type (AGENTS.md §2d, grammar.md) |
| `config_input` | rc≠0 within ~1 s of spawn AND the capture carries a provider/alias config-error marker (`Unknown provider '<alias>' …`) | `node.failed` on the FIRST attempt — outside both ladders, the respawn budget never burned; the error names the fix | fix the node's `provider` pin or the seat config the error names (AGENTS.md §3d) |
| `crashed` | a death no child turn owns: adopted child with an empty log, an external signal (`death_class: external_kill`, signal named), or a runner exception at `on_exit` | the node record / the runner's terminal verdict; `log_path` rides the record | read the named log, fix what killed the process (launcher path, OOM, host), re-drive (operations.md) |
| `declared_failure` | the child's own `node_outcome` token declares failure despite rc=0 — the node's verdict outranks the exit code | `node.failed`, deterministic: outside BOTH retry ladders; the child's `final` words ride the record | read the child's failure tail, fix its work, amend the node (grammar.md, WF-GRAFT-2 law) |
| `early_death` | silent for 120 s after spawn: "child produced no output within 120 s of spawn", killed, log empty — never got past its first call | `node.failed`; ONE machine-resume re-drive only when tool-progress evidence exists | check the route/launcher health the child could not reach, re-pin model/provider by amend — the bounded ladder already spent its one pass (AGENTS.md §3d) |
| `effect_receipt` | commit-edge demote `effect_receipt_unproven: <file>: missing / empty / N B < min_bytes M / sha256 mismatch` | `node.failed` on a node declaring `effects`; the measured `effect_receipts` rows ride the record | produce the named artifact for real and re-drive — the gate reads bytes itself, never prose (grammar.md) |
| `fanout_empty` | a fan-out resolved to zero items at spawn | `node.failed` + the run-dir `abort.json` flag (unless an `on_fail` arm catches it): the run FAILS, never a silent idle | fix the `items`/`items_from` source (the router that fed it), or give the node an `on_fail` else-arm (grammar.md) |
| `fatal_quota` | a 429 whose own text carries a reset horizon beyond the run's reach | `node.failed` on the FIRST attempt; the model is stamped into the seat quota cache and the door refuses a re-launch on it until the horizon passes (one recovery ping first) | wait the horizon out or re-pin another model (AGENTS.md §3d) |
| `forbidden_model` | the served/committed model sits on the seat's forbidden list (served-model policy gate) | `node.failed`; the record names the served model | re-pin a provider/model the seat allows, or lift the seat forbid (AGENTS.md §3d) |
| `incomplete_work` | done/partial over a declared `repo:` lane that still carries uncommitted TRACKED changes — the false hand-off is refused at commit | `node.failed` with the `lane_dirty` porcelain on the record | commit in the lane, then amend/re-run re-drives the node (grammar.md, `repo:` law) |
| `inputs` | an `inputs:`/`items_from` dotted path that never resolved at spawn — head never committed, or committed `done` without that path (the #473 skipped-sentinel is the ONE exception) | `node.failed` before the child ran, `attempts: 0` | fix the ref or the `after` edge; a head that committed `skipped` arrives as a labelled sentinel block, not as a death (grammar.md) |
| `item_record` | fan-out aggregate refused `done`: "per-item records do not back the claimed completion" — `record_problems` enumerates per index | `node.failed` with `record_problems` (missing, spawn-frozen, efp-invalid, or diverging from `all_results`) | re-drive the node so every item commits; read the per-item records the error names before rebuilding (grammar.md) |
| `killed` | "killed by lane kill (action=kill)" — the node-targeted kill, before or after spawn | the node record; terminal, never retried — the kill was an operator act, not a verdict on the work | amend the node to re-drive once what motivated the `kill` is resolved (operations.md) |
| `lane_wreckage` | a (re-)drive refused at STARTUP: a declared `repo:` lane still carries the dead attempt's uncommitted TRACKED wreckage (the #80 boot-sweep) | admission refusal BEFORE any Popen — no spawn, no silent continue; the error names the dirty files and both banking paths | `git stash push -m redrive:<run>:<node>` in the lane, or bank a patch at `<run>/wip/<node>.patch`, then re-drive (grammar.md) |
| `lease_busy` | rc=130 carrying the CLI's own notice "Stopped waiting for another Hermes process on this session. Your message was not processed." — a pure session-lease collision, never a verdict | `node.retrying` first, then the record if the re-drive harvests nothing: ONE bounded re-drive as a FRESH session (`#a{n+1}`, never `--continue` of the busy lease) | usually self-heals on the bounded re-drive; if it persists, end the other Hermes process holding that session lease (AGENTS.md §3d) |
| `left_live_descendants` | the child BACKGROUNDED the real work: an exit-0 spawn over a non-empty /proc tree — verdicts come from the tree, never from progress prose | `node.failed` (terminal — never re-driven by either ladder); a fenced answer over the live tree instead commits `partial` WITH this class and `tree_proof: dead` | let the ladder kill and prove the prior tree dead (or do it yourself), then re-drive; an unreadable /proc fails closed, never reads empty (AGENTS.md §3d) |
| `malformed_turn` | "reply is a serialized tool call rendered as text (tool-call-as-text; not harvestable)" — on fresh and adopted deaths alike, same class on every path | `node.failed`; rides the bounded re-drive ladder (one pass) | the ladder's one re-drive is the first repair; recurring means investigate the model's turn shape, not the graph (grammar.md) |
| `precondition` | an unmet output precondition with ZERO spawns — `precondition unmet: <ancestor>.<path>`, `blocked_by_partial_ancestor: <id>`, `publisher_ungated: <id>`, or `join parent failed: <ids>` | `node.failed` before spawn; `output.missing` lists the paths / ancestors | supply the missing ancestor output by amend, opt in with `after_partial: true`, or route the suite proof upstream (grammar.md) |
| `provider_400` | a provider 400 in the capture; stands only when nothing clamped — a server-named reasoning vocabulary already took ONE clamped-`--reasoning` re-drive | `node.failed`; the server's own message rides the error text | read the server's list and pick from it (the supported level or route for that pin) — never re-submit the refused value and hope (AGENTS.md §3b) |
| `quorum` | a fan-out under its commit bar: "<n>/<m> items failed: …" (`_quorum_death_label` names whether the bar was explicit or the majority default) | `node.failed` with `failed_detail` per item AND the survivors in `output.items` — partial credit is already banked | read `failed_detail`, fix the flaked items' inputs, re-drive; never set `quorum` on an every-item contract (operator-playbook) |
| `ratelimit` | the credential-window banner `… credentials are rate-limited for <model> …` — parks at jittered ~5-min intervals first (`node.retrying … backoff_s=N`), wall re-checked, spawn clamped after every park | `node.failed` on give-up, carrying the VERBATIM banner plus `ratelimit_banner` | switch model or credential — the banner is the dispatcher's switch signal; a bare requeue re-parks the same window (AGENTS.md §3d) |
| `route_inexpressible` | "pins <route> but this host's spawn argv CANNOT EXPRESS it" — neither `-p` profile evidence nor `-m`/`--provider` can carry the pin (the est-yq2xq strip face of #483) | `dispatch.refused` + `node.failed`, ZERO attempts — refused before the child started | point the node at a profile the host resolves, lift the omit-policy-flags marker/env, repin an expressible seat, or accept fallback with `require_route: false` ON THAT NODE (grammar.md) |
| `route_substitution_denied` | a post-admission spawn would bill a route OTHER than the door-proved-alive receipt — no silent re-billing of another model | `node.failed` BEFORE submit, `attempts: 1` | amend the node to the route you accept, or delete the run's route receipts only to re-admit through the door's ping (grammar.md) |
| `route_unavailable` | the door's ping affirmatively proved a pinned route dead (or answered from the fallback ladder), or a committed `served_model` contradicts the alive-proof (commit hold) | a submit-time LAUNCH REFUSAL at the door, or `node.failed` at the commit hold — never silent fallback billing | repin to a live route, or opt into the ladder explicitly with `require_route: false` (AGENTS.md §3d) |
| `schema` | the fenced reply fails the answer contract a SECOND time (first offense takes the one typed correction retry) — type, enum, or minLength/minItems bound | `node.failed`; the violation is named; `output` and `raw` ride the record | fix the `schema` or the goal that produced the off-contract reply, then re-drive (grammar.md) |
| `seat_cap` | the seat-cap knob (`WORKFLOW_MAX_SEATS` env / config `workflows.max_seats`) named a non-integer or a value outside [4, 64] | the DOOR refuses the whole launch before any write or spawn (a mid-run flip fails the node); never silently defaulted to `SEATS_DEFAULT` | fix the knob value at its source — env, .env, or config (AGENTS.md §3d) |
| `seat_unsupported` | the semaphore was full and the host exposes NEITHER /proc NOR `ps` — a nested runner cannot prove which held seat is its own lending ancestor | refused at once instead of deadlocking to `seat_wait` — nested runners on such a host are unsupported | run nested runners only on ancestry-readable hosts; there, set `WORKFLOW_MAX_SEATS=0` (AGENTS.md §3d) |
| `seat_wait` | the global agent seat (`WORKFLOW_MAX_SEATS`) never freed within the node's wall — the spawn never happened and spent ZERO tokens | `node.failed`; clocks read `exhaustion_reason: queue_timeout` and `ms` is queue duration, not child work | re-drive when seats free and stagger same-seat waves — admission starvation, never edit the def to chase it (operator-playbook) |
| `spawn` | "launcher spawn failed" — `hermes_bin` absent at the path frozen in run.json, or "profile gone: <name>" (target deleted before Popen; never a silent launcher fallback) | `node.failed`, `attempts: 1`, the seat ticket released | repair the frozen `hermes_bin` / spawn cwd in run.json (`amend` never rewrites run meta) or restore the profile, then re-drive (operations.md §trust boundary) |
| `stale_graph` | a spawn that queued on the seat reached the Popen instant AFTER an amend moved its effective fingerprint — the queued definition never launches | a typed refusal event (seat ticket released, outside both ladders); the wave boundary then consumes `restart.request` and RE-DRIVES the node under the CURRENT definition | usually none — it self-heals at the wave reload; a permanent refusal means the queue stays saturated across every amend (AGENTS.md §3d) |
| `timeout` | the wall fired (one 50 % `node.extended` grace first only while the child was still writing); the corpse is banked per #131 | `node.failed` with `banked` → `nodes/<id>[.<i>].corpus/` (`work/`, `stdout_tail.txt`, `manifest.json` — `last_written` first) + one `node.banked` event | amend the goal to a RESUME prompt naming what is already banked and forbidding its redo — cold re-runs of a timed-out lane time out again (AGENTS.md §3d) |
| `transport` | a transient provider death (503 shape), or an rc=0 capture carrying a transient sentinel — "exit 0 is not success"; the `sentinel` field names the marker | `node.failed` after the zero-progress ladder, or `node.retry` with the machine-resume preamble on tool progress (fresh-session shape when the prior session banked nothing, #102) | usually the ladder already healed it; standing reds mean check the provider, and only then walk the `fallback_models` ladder (AGENTS.md §3d) |
| `transport_exhausted` | the node's persisted attempts already met its transient cap before this boot — the respawn grant is spent (read-model `refusal: lifetime_cap_spent`) | the node record; FINAL by law: the `fallback_models` ladder does not walk rungs over it | fix the transport/provider, then re-drive with a fresh ledger (new run, or the amended definition) — the same graph re-runs die identically (AGENTS.md §3d) |
| `unknown` | the harvest-time default: an untyped death — no capture marker matched, no typed turn-report stamp (an untyped turn-cap budget death lands HERE) | the node record; `status` reports `turn_report: typed\|untyped` so you can tell honest absence from a gap | read the record's `log_path` for the real death; apply the one-field core patch (AGENTS.md §2d) so budget deaths arrive typed (AGENTS.md §2d) |
| `unresolved_model` | the child's capture says the model name resolved to no route ("unknown model", alias preflight to the wrong bare name) | `node.failed`; the matched marker line rides the error | pass explicit `provider` + literal `model` — an alias's TARGET can resolve differently than the alias itself (operator-playbook §Ergonomics) |
