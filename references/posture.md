# Posture — why the mechanics are shaped this way

The mechanics live in the mechanics references ([battle cards](mechanic-battle-cards.md),
[grammar](grammar.md), [operations](operations.md)). This page is the philosophy appendix:
the posture each mechanic encodes. It names no tool, no host, no deployment.

**The ledger, not a tool.** Every law speaks of *the ledger* — the record of what ran, what
committed, what woke whom. Whichever tracker stands behind it is a deployment choice; the
laws never name one, so they survive the swap.

**Numbers are shapes, never headlines.** Budgets and widths travel as shapes
(`shape:recon|build|review|publish`) sized from measured presets; a hand-typed count is a
headline that rots on the next lap. Totals point into the enumeration, never restate it.

**A husk is a mechanism that survives its own query.** Ask of any shipped part: *which
check goes red if I delete this?* If nothing answers, it is a husk — form without law.
The query is the definition; this repo's honest answer is always a file under `tests/`.

**A wedge is the check that keeps a law true.** Ask of any law: *what goes red when this
rots?* The named test, the scrub audit, the door's typed refusal — that is the wedge.
A law with no wedge is a preference wearing a law's coat.

**Every law pairs with a receipt the package itself holds.** Not a chat log, not a memory:
the test that fails at the base commit, the event line in the run ledger, the `wake.jsonl`
row, the committed node record. A claim that cannot cite a shipped record is prose.

The same stance ships in table form as `docs/posture.md` in the repo docs tree; that
copy documents the stance layer but does not ride the pack ZIP — this appendix is the
shipped copy. One evidence base behind both; keep them honest to each other.
